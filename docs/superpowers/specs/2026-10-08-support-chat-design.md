# 人工客服实时聊天设计

## 目标与范围

在现有 Spring Boot / Vue 商城中实现登录买家与后台管理员的文字聊天。买家帮助页保留 AI / FAQ，增加独立的人工客服入口；后台新增 `/admin/support` 会话列表和消息面板。第一版所有管理员均可处理会话，每个买家共用一条长期会话，不做客服分配、图片、已读回执和消息删除。

成功标准：买家发送消息后后台实时收到，管理员回复后买家实时收到；刷新、断线或后端重启不丢已保存消息；买家无法读取或发送到他人会话。

## 方案选择

采用 HTTP 保存和查询消息、原生 WebSocket 推送已保存消息。发送使用现有 Axios 鉴权和令牌刷新机制；WebSocket 承担实时通知，不另建发送事务协议。相较纯内存转发，该方案支持历史和离线留言；相较 STOMP / 消息代理，所需依赖和部署更少。

后端增加 Spring Boot WebSocket starter；前端使用浏览器原生 WebSocket。沿用现有 Controller / Service / Mapper / DO 分层、CommonResult、MyBatis-Plus 和 Element Plus。

## 数据与接口

增加 `mall_support_message`，包含主键、买家 ID、发送者 ID、发送者角色、文本、客户端消息 UUID、创建时间，以及项目基础审计字段。数据库唯一约束为买家 ID、发送者角色、发送者 ID、客户端 UUID，避免请求重试产生重复记录；按买家 ID 和消息 ID 建索引。

消息最多 2000 字，必须非空；客户端 UUID 必须合法。用户身份全部由服务端登录信息确定，客户端不能指定发送者角色或 ID。

- 顾客：`GET /mall/client/support/messages` 查询自己的历史，`POST /mall/client/support/messages` 发送自己的消息。
- 管理员：`GET /mall/admin/support/conversations` 分页查询会话，按最近消息排序；`GET /mall/admin/support/messages?userId=...` 查询指定买家历史；`POST /mall/admin/support/messages` 给指定买家回复。
- 历史每页最多 50 条，按消息 ID 游标查询，支持向前加载旧消息以及断线后向后补取新消息。返回稳定的消息 ID、会话买家 ID、发送者角色及展示名、正文和时间。
- `POST /mall/support/ws-ticket`：已登录用户获取随机一次性短期票据，绑定当前身份，60 秒过期；限制同一身份的未消费票据数量并清理过期票据。
- `GET /mall/support/ws?ticket=...`：只允许有效票据升级连接，一次消费后不可复用。握手校验同源 Origin；本地 Vite 和生产反向代理均通过同源路径访问。

现有 `/mall/client/support/**` 全部公开的匹配改为只公开既有 AI `/status` 和 `/chat`。新增 HTTP 接口按买家 / 管理员角色检查。WebSocket 升级入口只在安全链路中放行握手，处理器必须验证票据；不把登录访问令牌放在 URL 中。

## 消息流程与失败处理

1. 页面进入后取得票据并建立 WebSocket，连接成功后同步数据库历史。推送和历史按消息 ID 去重，避免连接期间漏消息或显示重复。
2. HTTP 发消息先验证身份和内容，提交数据库后才向该买家的所有连接和在线管理员推送。HTTP 返回保存后的消息，作为发送确认；前端不以推送到达作为发送成功条件。
3. 网络失败时保留输入内容并显示失败，重试使用原 UUID；数据库拒绝或事务失败不得推送。推送失败不回滚已保存消息，后续重连从历史补齐。
4. 客服离线仍可留言，界面明确显示离线状态。管理员连接和断开时通知买家在线状态；有多个管理员时按是否至少一个在线判断。
5. 连接定时发送 ping / pong，超时关闭并重连；前端使用有上限的退避，组件卸载或退出时清理连接、定时器和监听。认证失败先沿用现有刷新流程，刷新失败则要求登录，避免无限重试。
6. 单连接发送串行化并限制缓冲，慢连接关闭后通过历史恢复；票据所绑定访问令牌过期后关闭连接，重连重新认证，避免连接无限延长登录权限。

## 页面行为

买家帮助页增加 AI / 人工模式切换，未登录时引导登录。人工消息列表显示买家和客服消息，支持加载更多历史、发送状态、连接状态及客服离线提示。切换模式保留现有 AI 行为，不将 AI 历史发送到人工会话。

后台在桌面及移动导航新增客服入口。会话列表显示买家名称、最近消息和时间，管理员选择会话后查看历史并回复。未打开会话收到推送时更新会话列表；打开的会话追加消息。无需单独的客服账户类型。

文本通过 Vue 插值渲染，不使用 HTML 渲染聊天正文。按钮和输入框具备标签、禁用状态及键盘提交能力；新增文案接入项目 i18n。

## 实施触点

后端涉及 pom、SecurityConfig、人工聊天 Controller / Service / Mapper / DO、WebSocket 配置及处理器；复用 TokenService，不改变现有 HTTP TokenAuthFilter 的认证规则。前端涉及帮助页、后台客服页及路由 / 导航、聊天 API 和连接生命周期工具、Vite 的 `/mall` 代理 WebSocket 升级、i18n。README 补充接口、部署和建表步骤。

当前 README 明确建表脚本不进入仓库，因此文档给出新表结构和约束，供本地 / 部署数据库执行；不自动修改现有数据库。保留工作区已有未提交改动，不做无关重构。

## 验证

新增必要的测试依赖和小范围测试：买家会话隔离、管理员权限、空白及超长消息、一致的 UUID 重试结果、保存失败不推送、票据过期 / 重用 / 角色绑定、过期连接清理。验证历史游标顺序与补消息去重，进行前端生产构建和后端测试。

条件允许时使用买家与管理员两个会话验证双向消息、离线留言、刷新恢复和断线重连；如果无法连接开发数据库或缺少运行密钥，明确报告未完成的联调项，不声称联调通过。

## 部署限制

第一版仅支持单个后端实例，票据及在线连接在进程内；数据库保存消息。生产代理必须转发 Upgrade / Connection 头并提供合适的长连接超时，HTTPS 使用 wss。未来多实例部署需要共享票据和跨实例广播，届时才增加 Redis 分发。

本次只创建实现和部署说明，不部署网站，不改生产数据。所有管理员均能看到全部客服会话，后续需要专职客服权限或分配规则时另行扩展。
